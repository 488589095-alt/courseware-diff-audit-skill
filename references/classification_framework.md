# 差异三分类框架（A/B/C）—— 本 skill 的分析内核

> 脚本只产生**机械事实**（讲义有 X / 课件未命中 X / 标杆第 n 页有 X）。
> 「该不该有、是 bug 还是合理增量、根因是什么」全部由你（Claude）按本文件判定。
> **裁判是讲义**：一切归因都先问「讲义里有没有」。

## 三分类定义

| 类 | 讲义 | 标杆 | 模版 | 判定 | 处置 |
|---|---|---|---|---|---|
| **A** | 有 | 有 | — | 课件**必须有** | 标杆有而课件 miss/错 → **生成 skill 的 bug**，**必出补丁** |
| **B** | 无 | 仅标杆有 | — | 老师人工精备增量 | 课件**不该凭空生成** → 正常忽略，记入 R2 表；**不是 bug** |
| **C** | 有 | 有 | **无槽位** | 讲义有内容但模版没有对应版式/文本框 | 应**按标杆样式新增**；已补=PASS，未补=出补丁 |

B 类的典型物（来自历史 case，跨学科稳定复现）：
课前测/课后测/入门测/出门测、选择题的**干扰项**、5 步流程图/STEP 推理框、
插画/吉祥物/星星图、游戏化标签（青铜/黄金/水平）、「你会怎么表达?」过渡页、
中文语篇翻译（讲义只给英文时）、S 班/A+ 班页码、**填好的**推断答案/情节切分表
（讲义对应表是**留白**的）。

## 把机械事实映射成 A/B/C 的判定流程

对 `completeness.json` 的每个 **miss / image_check** 项、`structure_diff.json` 的每个
**benchmark_only 页**、`style_diff.json` 的每个**偏离**，依次问：

1. **讲义里有吗？**（看 completeness 该项 type/section；或 grep 讲义 dump）
   - 没有 → **B 类**（老师增量），记 R2，**不出补丁**。结束。
   - 有 → 进 2。
2. **模版有对应槽位吗？**（看 template_spec.json 的 layouts；没有 spec 就看标杆是不是靠自绘文本框实现）
   - 没有槽位 → **C 类**：课件应按标杆样式新增。看课件是否已补 → 已补 PASS；未补出补丁。
   - 有槽位 → **A 类**：课件本该直接回填却 miss/错 → **bug，出补丁**。
3. A/C 类一律写**四段式诊断**（见下）并定位到目标 skill 的文件/函数（见
   [target_skills_map.md](target_skills_map.md)）。

## 四段式诊断（A/C 类每条必写，沿用 ppt-script-fix 纪律）

```
问题：[现象——引用机械证据 + 并排截图，如 completeness.json#H-003 / _cmp/p3_vs_c2.png]
根因：[代码层原因——哪个脚本/函数没处理这种内容]
受影响场景：[会触发该段代码的所有内容类型，不止这一例]
修改后影响：[修复可能波及的原本正常的情况]
```

**先 Read 完所有证据（三份 JSON + 缩略网格 + 并排图）再下诊断**，一次设计覆盖所有场景的修复，不做试探性小改——图片位置/溢出/字体这类启发式，改一处易破坏另一处。

## 边界口径（4 个高风险情形，防误判 —— 必读）

### 边界 1：讲义有 + 标杆**无** + 模版无（非标准 A/B/C）
这是**项目口径问题，脚本与你都不可擅自判 bug**。两种合法口径并存：
- **「贴标杆」口径**（如**古诗**case）：标杆没有的就不放，即使讲义有。
  → 此时讲义的「知识精讲/炼字概述/命题角度/词类作用表/每题【解析】」虽 completeness 报 **miss**，
  但因**标杆也没有** → **按贴标杆策略归为「忽略」，绝不能判成 A 类 bug**。
- **「讲义全覆盖」口径**（如**英语第9讲**case）：讲义有的一律转入，标杆没有也做（按 C 类新增）。
  → 此时同样的内容就要判 A/C，出补丁。

**做法**：报告里**显式声明本 case 采用哪种口径**（默认沿用该 case 历史产物/README 的口径），
再据此分类。证据：先看 `structure_diff.json` 的 `role_histogram` —— 若**标杆也几乎没有「答案/解析」角色页**，
说明标杆走精简口径，则讲义的解析类 miss → 归「忽略」。

### 边界 2：图片类内容（completeness 标 `image_check`）
讲义内嵌图（Knowledge Map/思维导图/几何图/结构简式）**无法靠文本匹配**。
脚本标 `is_image=true` 且 miss → status `image_check`。**必须看并排截图目检**课件对应页有没有这张图，
再判 A（漏图=bug）/B（讲义本无图）。不要凭文本 miss 就判缺失。

### 边界 3：页数差额账目（structure_diff `page_count`）
- **以 `role_delta` 为准**（每页唯一角色，Σdelta 恒等于 total_delta），不要用 `benchmark_only_by_binding`
  —— 标杆的增量页（如选择题）常与课件**共享同一篇语篇文本**，相似度绑定会把它们误绑为「有对应」，
  导致 `benchmark_only_by_binding` 偏小。
- `role_delta` 里**标杆多出的角色**（选择题/方法讲解/测评…）就是 5 类老师增量的机械证据，逐条对到 B 类桶。
- 若 `warn_unbucketed` 为真（未归类增量页偏多）→ 必须看这些页的截图人工细分。

### 边界 4：partial 不等于缺失
completeness 的 **partial** 多为：① 短**章节标题**未精确子串匹配（内容其实在）；
② **留白表格**（讲义给填好的表头+内容，课件按讲义留空 → 表头匹配、内容不匹配）。
看 `summary.by_type`：**真正的 A 类强信号是「答案/注释/正文」类的 miss**，不是 partial，也不是标题/表格的 partial。
content_coverage 比 coverage 更能反映内容是否转入。

## 字体回退（style_diff 硬规则，跨学科通用 = A 类样式 bug）
`字体:中文回退等线` FAIL = 有**中文 run** 的 `a:ea` typeface 是「等线/DengXian」→
WPS/PowerPoint 打开时中文显示成等线（非设计字体）。这是生成 skill **没显式设 ea** 的 bug，
**与学科无关**（无论该科用楷体/黑体/普惠体，都不该回退等线）。直接出补丁：在渲染函数里对中文 run 显式写 `a:ea`。
（注：纯英文 run 的 ea=等线无害，脚本已排除；只看含中文的。）
